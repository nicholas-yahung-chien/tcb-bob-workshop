# Bob 演練方法與驗收判準

以 Bob Shell 2.0.2 實際呼叫 AI 服務，使用 Windows 使用者環境中的 BOB_API_KEY。每輪從相同教材建立新工作區，不帶入 output 或 reference；每個步驟以獨立對話執行，檔案在輪內保留。這比依赖上一段對話記憶更容易重設與追查。

Ask、Plan、Agent 分別呼叫；正式文件由 Agent 落檔，避免把 Plan 工具的路徑限制當成故障。每步最多45回合、600秒。記錄狀態、耗時、工具次數、驗收結果與受保護檔案雜湊；CLI exit code 0 不等於驗證成功，輸出中的 error 事件也算執行異常。

驗證分為三層：

1. **機械驗收**：欄位值、精確引文、Markdown 控制字元、JSON 契約、合成 log 分類、檔案完整性。
2. **程式驗收**：11個獨立行為測試、至少3個 Bob 新增測試、6個 SQL 參數綁定與回歸測試。測試直接檢查輸入與輸出，不讀實作碼猜測結果。
3. **人工審查**：來源是否支持結論、未知是否誤寫成不存在、七領域是否具體、主機驗證是否如實保持未完成。引文出現在檔案內，仍不代表它支持整段文字。

初期演練發現與處理：

| 觀察 | 教材處理 |
|---|---|
| R-ID 群組11位被當成10位 | Prompt要求計算REDEFINES與R-ID-2；計畫保留source-check，文件另外驗收10位子欄位 |
| EOF位置被歸到R-PID | 逐項列R-NAME的12–51位並核對來源 |
| 把每筆REWRITE誤認只有異動才寫 | 明確分析IF句點範圍，區分原程式I/O與Python written |
| PowerShell字串處理損壞Markdown反引號或形成控制字元 | 要求原文寫檔，驗收拒絕控制字元；保留帶證據修正步驟 |
| JSON加入說明、引文前導空白與原文不一致 | 正文與契約分離；直接引用原行片段；失敗時給實際驗收訊息 |
| 30回合上限被大量補充測試耗盡 | 補充測試收斂為3項，課前演練上限45回合；異常仍如實保留 |
| 來源未提供備份／鎖定卻被寫成一定沒有 | 人工規準要求區分「未提供」與「不存在」 |
| 推論CKP02既有檔案組織、誤稱日期減10000為365天 | 進階題要求圖文一致保留未知，直接描述數值運算 |
| 進階題把未讀程式猜成某種業務、誤算日期與混淆WORKING-STORAGE | 限定四段摘要，人工逐行指出錯誤，再請Bob重讀修正；提供精簡審訂答案 |

失敗後使用09-repair加上真實驗收輸出與人工審查意見，要求只修改output。重新執行相同驗收，並再次檢查來源、測試、規格與工具未被修改。發布前以最後版驗收工具重新檢查演練產出；報告區分原輪驗收與發布版驗收，不把更新工具造成的新增失敗藏掉。

這些演練是小樣本，不能保證未來每次模型回覆或服務延遲一致。工作坊的一致成果靠固定教材版本、明確契約、驗收、修正與參考答案共同維持。Python模型與SQLite測試不等於主機COBOL、IMS、Premium for Z或正式SAST引擎驗證。
