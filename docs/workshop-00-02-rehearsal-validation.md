## 01：可閱讀資料字典的來源核對

本次 Bob 已產生 output/CKP02-data-dictionary.md；首次產物的來源核對發現下列落差，不能以檔案存在判定內容已驗收通過：

- 文件第 65 行開始的 Working-Storage 分類包含 CH-RPD-KEY、R-ID-1、CH-R-ID-2，這三項實際宣告於 CKP02 第 21、26–32 行的 FILE SECTION；WORKING-STORAGE 始於第 53 行。
- 第 114 行只用 CH-RPD-KEY 成立說明轉換觸發，漏掉原碼第 82–84 行的 NOT EOF 條件；文件第 187 行卻有完整條件，前後需要統一。
- DD.json 將 RPD 展開為 Registered Party Detail；原碼只有識別字與公司統編註解，沒有證實這個英文全名。正文沿用 AI 名稱或依欄位縮寫推測用途時，需要明示待確認。
- 第 35 行將表中子欄位概括為 DD.json 未收錄，但表內包含實際已收錄的 R-ID-1、CH-RPD-KEY、CH-R-ID-2。
- 文件多處使用 `z-lab/CKP02.cbl` 作為相對連結；文件位於 output/，應從該目錄解析成 `../z-lab/CKP02.cbl`。

以上是本次模型產物的內容與連結問題，不是所有版本必然發生的產品缺陷。教材的 data-dictionary-zh-tw 技能與 PPZ 指引補上對應核對標準。經具體來源提示修正及獨立複核，最終可閱讀資料字典的上述五類問題均已修正；原稿保留，DD.json 與來源程式未變更。

原教材的 Ask 核對提示在本次實際回覆「資料字典內容正確，無錯誤需要更正」，漏掉上述五類問題。第一次具體修正後，業務語義仍殘留於摘要、表格及標題；再次對照來源後才一併修正。這次核對顯示，詳細段落加上待確認，仍不足以證明全文一致。

因此教材的 Ask 核對提示也改為逐項列出文件位置、來源依據與判斷，涵蓋上述五類檢查；不能把一次通用自我檢查的成功回覆，當作內容已正確的證據。
