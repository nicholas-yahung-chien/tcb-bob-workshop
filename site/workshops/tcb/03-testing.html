測試與修正

換一筆資料，結果還對嗎？

從現有測試出發，看看正常、例外和重跑時的結果。

除了正常資料，還要試哪些情況？

程式看起來合理，還需要用資料試試看。先用自己的主機帳號執行 CKP02，比較預期與實際結果；完成後，再選做補測試與本機需求練習。

在主機跑一次 CKP02

先完成個人主機連線。開啟 CKP02 與 z-tests/fixtures.json 的七筆測資，先和 Bob 討論結果。

Ask 模式

加入檔案：z-lab/CKP02.cbl、z-tests/fixtures.json

先預測結果
我準備在主機執行 CKP02。請根據程式和這七筆測資，說明第一次、第二次執行後各會得到什麼，並指出程式依據。資料中的 EOF 和讀到檔尾有什麼不同？
預期回應

七筆資料兩次執行的預期結果，以及程式依據。

把剛才讀的程式存入主機

接下來執行的，就是同一份 z-lab/CKP02.cbl。本機檔案保留 UTF-8 與 LF，透過 tcb-zosmf 以 IBM-937 存入自己的來源資料集，中文註解也一起保留。

  1. 開啟本機 z-lab/CKP02.cbl，確認右下角為 UTF-8、LF，按 Ctrl+A、Ctrl+C 複製完整內容。
  2. 在 Zowe Explorer 的「資料集」展開 tcb-zosmf，搜尋並開啟 <自己的帳號>.TCBLAB.SRC937。這是本次 CKP02 專用的循序資料集，不需要建立 member。確認名稱開頭是自己的帳號。
  3. 在主機資料集的編輯分頁按 Ctrl+A、Ctrl+V，將內容換成本機 CKP02，確認換行為 LF，再按 Ctrl+S 儲存。保留本機 z-lab 檔案不變。若既有內容是自己的修改，先保留修改，不直接取代。
  4. 關閉主機資料集分頁，重新整理後再開啟，確認 PROGRAM-ID. CKP02.、中文註解「公司統編時，轉換格式」及檔案最後一行均與本機一致。若多出空行、文字變成問號或出現截斷訊息，先保留錯誤畫面，確認連線與換行後再繼續。

找不到 SRC937 時，先核對帳號與搜尋條件，再請講師協助。此步只更新自己的來源資料集；稍後 JCL 從這裡編譯 CKP02，不會使用另一份 CKP02 範本。

準備並提交作業

接著加入自己的 environment.md，請 Bob 依 BOB-GUIDE.md 從 z-tests/run.jcl 建立個人 JCL，不需 Python。作業會在主機編譯程式、執行兩次轉換與一次空檔測試，使用各作業獨立的暫存資料集。

Agent 模式

加入檔案：host-lab/README.md、host-lab/environment.md、host-lab/BOB-GUIDE.md、z-lab/CKP02.cbl

準備自己的主機作業
請依 host-lab/BOB-GUIDE.md 和我的 environment.md，為剛才存入主機的 z-lab/CKP02.cbl 建立個人 JCL，不使用 Python。請確認編譯時讀取我的 SRC937，使用 CODEPAGE(937),DBCS。先不要提交，完成後帶我核對作業設定與測試步驟。
預期回應

尚未提交的 run.jcl，以及各步驟與個人配置的說明。

  1. 開啟 host-lab/run.jcl，核對 job 名稱、DEVVS1、SCNOSMS，以及 CCKP 的 SYSIN 是自己的 <帳號>.TCBLAB.SRC937，編譯選項包含 CODEPAGE(937),DBCS。
  2. 在編輯器按右鍵選 Submit as JCL，選 tcb-jobs（IBM-1047）連線。
  3. 記下回傳的 job ID，在 JOBS 的 tcb-jobs 核對 owner，等待 OUTPUT。
  4. 下載 JESMSGLG、JESYSMSG、CCKP 的 SYSPRINT，以及 CHECK1、CHECK2 的 SYSOUT，放在 host-lab/logs/<job ID>/，同名 DD 依 step 分開儲存。

將紀錄帶到下一單元，確認 RC 4 的來源、兩組七筆完整 400-byte 比對，以及 RUNEMPTY 的結果。請依本頁步驟操作，再到下一單元核對紀錄。

完成主機實作後，選擇延伸練習

1. 從現有測試開始補

TESTSHIFT 已經有幾個簡單案例。把它和 testing.md 一起加入對話，讓 Bob 沿用現有寫法。

Z Code 模式

加入檔案：specs/testing.md、samples/cobol/TESTSHIFT.cbl

補上 COBOL 測試
請參考 TESTSHIFT 與實際轉換邏輯，依 specs/testing.md 補上 COBOL 測試和案例說明，存到 output。每個案例列出輸入、預期結果和對應條件。

完成後說明哪些案例已執行、哪些還需要編譯或主機環境。
預期回應

COBOL 測試程式、案例說明及執行前提。

完成後會有 cobol-test-plan.md 和 TESTSHIFT-EXT.cbl。編譯執行需要 COBOL 環境；還沒執行的案例，先保留為待執行。

2. 在本機試跑轉換規則

以下為選做練習，另需本機 Python 3.10 以上；不影響前面的主機實作。Python 範例使用同樣的資料位置與轉換規則，可以在一般筆電執行。它也包含這次新需求的預覽與統計功能。

Agent 模式

加入檔案：requests/customer-email.txt、specs/testing.md

完成範例並跑測試
請依 specs/testing.md 中選做練習的介面約定，完成 Python 轉換範例並補上測試，存到 output。這些介面約定只用於本機練習。
預期回應

完成的 Python 範例、三個新增測試和實際測試報告。

Agent 模式

加入檔案：specs/testing.md

看看測試結果
請執行 specs/testing.md 裡的 Python 測試，說明哪些通過、哪些失敗，再把結果更新到測試報告。
預期回應

既有與新增測試的執行結果，並更新測試報告。

在 Bob 的執行結果中，應有 11 個既有測試與 3 個新增測試。開啟 output/test-report.md，看看測了什麼、結果如何。

3. 測試失敗時，接著怎麼問？

把完整的失敗訊息留在對話裡。Bob 已經有需求和程式，接下來只要針對這次失敗請它協助。

Agent 模式

加入檔案：output/

找出原因再修正
這是剛才的檢查結果。請幫我找出失敗原因，對照需求修正 output 裡的檔案，再跑一次相同的檢查。也請簡單說明你改了什麼。
預期回應

失敗原因、修改內容，以及重新檢查的結果。

測試通過後，再看一件事

預覽模式應保留原始資料，套用模式則回傳轉換結果。看看兩者的統計是否一致，也看看同一筆資料再跑一次的結果。Python 測試記錄和 COBOL 執行結果分開保存。
