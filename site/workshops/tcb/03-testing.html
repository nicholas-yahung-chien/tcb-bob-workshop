測試與修正

換一筆資料，結果還對嗎？

從現有測試出發，看看正常、例外和重跑時的結果。

除了正常資料，還要試哪些情況？

程式看起來合理，還需要用資料試試看。這裡先請 Bob 補上 COBOL 測試，再用本機的 Python 範例檢查相同的轉換規則。

1. 從現有測試開始補

TESTSHIFT 已經有幾個簡單案例。把它和 testing.md 一起加入對話，讓 Bob 沿用現有寫法。

Z Code 模式

加入檔案：specs/testing.md、samples/cobol/TESTSHIFT.cbl

補上 COBOL 測試
請參考 TESTSHIFT 與實際轉換邏輯，依 specs/testing.md 補上 COBOL 測試和案例說明，存到 output。每個案例列出輸入、預期結果和對應條件。

完成後說明哪些案例已執行、哪些還需要編譯或主機環境。
預期回應

COBOL 測試程式、案例說明及執行前提。

完成後會有 cobol-test-plan.md 和 TESTSHIFT-EXT.cbl。編譯執行需要 COBOL 環境；還沒執行的案例，先保留為待執行。

2. 在本機試跑轉換規則

Python 範例使用同樣的資料位置與轉換規則，可以在一般筆電執行。它也包含這次新需求的預覽與統計功能。

Agent 模式

加入檔案：specs/change-request.md、specs/testing.md

完成範例並跑測試
請依 specs/change-request.md 和 specs/testing.md，完成 Python 轉換範例並補上測試，存到 output。

新增案例請從需求推導輸入與預期結果，涵蓋正常情況及容易漏掉的邊界。完成後實際執行測試，記錄結果和修正內容，保留原有測試。
預期回應

完成的 Python 範例、三個新增測試和實際測試報告。

Agent 模式

加入檔案：specs/testing.md

看看測試結果
請執行 specs/testing.md 裡的 Python 測試，說明哪些通過、哪些失敗，再把結果更新到測試報告。
預期回應

既有與新增測試的執行結果，並更新測試報告。

在 Bob 的執行結果中，應有 11 個既有測試與 3 個新增測試。開啟 output/test-report.md，看看測了什麼、結果如何。

3. 測試失敗時，接著怎麼問？

把完整的失敗訊息留在對話裡。Bob 已經有需求和程式，接下來只要針對這次失敗請它協助。

Agent 模式

加入檔案：output/

找出原因再修正
這是剛才的檢查結果。請幫我找出失敗原因，對照需求修正 output 裡的檔案，再跑一次相同的檢查。也請簡單說明你改了什麼。
預期回應

失敗原因、修改內容，以及重新檢查的結果。

測試通過後，再看一件事

預覽模式應保留原始資料，套用模式則回傳轉換結果。看看兩者的統計是否一致，也看看同一筆資料再跑一次的結果。Python 測試記錄和 COBOL 執行結果分開保存。
