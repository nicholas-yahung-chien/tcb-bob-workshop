先從 CCKP 的 SYSPRINT 核對 CODEPAGE(937) 與 DBCS，確認編譯來源是自己的 TCBLAB.COBOL(CKP02)。JESMSGLG、JESJCL、JESYSMSG 從 tcb-rse（IBM-1371）開啟；CHECK1、CHECK2 比對紀錄也從 tcb-rse 開啟，識別值以雙引號包住，例如 ACTUAL-ID="12345678 "。CCKP 編譯清單從 tcb-rse（IBM-1371）開啟，以正確顯示中文註解。

GENERATE／SYSOUT 使用 tcb-rse；中文 PRINTDD 同樣從 tcb-rse（IBM-1371）開啟。GENERATE／PRINTDD 使用中文 IBM-937 測資，每筆以單一完整 400-byte 資料行印出；前後雙引號用來保留尾端空白，不屬於資料。中文包含雙位元字元與 SO／SI 控制碼，因此解碼後的字數、畫面欄號不等於主機 byte 位置。GENERATE／SYSOUT 另外顯示 CASE、ID 與 EOF-MARKER-AT-014=YES/NO，表示第 14–16 bytes 是否為 EOF；不直接印出可能切到半個中文字的三個 bytes。CASE 0003 為 YES，所以不轉換；CASE 0005 的 EOF 位於第 12–14 bytes，判斷為 NO，仍轉換。公司、姓名、地址及備註均為虛構中文；未知代碼留空，數字欄位保留數字。這是測資輸出，尚未實作需求中的預覽功能。

每筆輸出中的 BEFORE-ID 是這一次執行 CKP02 前的實際識別值，ACTUAL-ID 是執行後的實際值，EXPECT-ID 是預期結果。CHECK2 的 BEFORE-ID 來自第二次執行前的快照，應等於 CHECK1 的 ACTUAL-ID。

BEFORE-ID="0000123456"
ACTUAL-ID="00123456  "
EXPECT-ID="00123456  "

CHECK2 / CASE 0004
BEFORE-ID="00123456  "
ACTUAL-ID="123456    "
EXPECT-ID="123456    "

先從 JESYSMSG 確認 SNAP1、SNAP2 都有執行且 RC 0。這份輸出呈現識別值的前後差異；PASS 仍代表整筆 400 bytes 符合預期，不是只比對顯示的十個字元。

CHECK1、CHECK2 應各有七筆 PASS ALL 400 BYTES，結尾為 CHECKED=0007 ERRORS=0000；RUNONCE、RUNTWICE、RUNEMPTY 均應 RC 0。CCKP 的 RC 4 必須與 README 列出的編譯警告核對，不能只看整體 return code。

CKP02 沒有呼叫 IMS，因此這些紀錄不能用來判斷 IMS 交易是否完成。若缺少某個 step 的紀錄，先從相同 job ID 補下載，再請 Bob 接著確認。
