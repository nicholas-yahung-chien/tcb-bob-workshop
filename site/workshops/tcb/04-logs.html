Ask 模式

加入檔案：host-lab/run.jcl、host-lab/logs/、host-lab/README.md、host-lab/BOB-GUIDE.md

核對自己的執行結果
這是我剛執行 CKP02 的主機紀錄。請依 host-lab/BOB-GUIDE.md 幫我確認哪些步驟真的有執行、RC 4 來自哪裡，以及兩次比對和空檔測試是否成功。請指出 job ID、step 和對應訊息；缺少的紀錄先列為待確認。
預期回應

依實際 job、step 與訊息核對的執行結果，以及仍需補充的紀錄。

先從 CCKP 的 SYSPRINT 核對 CODEPAGE(937) 與 DBCS，確認編譯來源是自己的 TCBLAB.COBOL(CKP02)。JESMSGLG、JESJCL、JESYSMSG 從 tcb-jobs（IBM-1047）開啟；CHECK1、CHECK2 比對紀錄也從 tcb-jobs 開啟，識別值以雙引號包住，例如 ACTUAL-ID="12345678 "。CCKP 編譯清單從 tcb-rse（IBM-937）開啟，以正確顯示中文註解。

GENERATE／SYSOUT 使用 tcb-jobs；中文 PRINTDD 依上一單元的 CLI 步驟先讀取，再從 tcb-rse（IBM-937）開啟。GENERATE／PRINTDD 使用中文 IBM-937 測資，每筆以單一完整 400-byte 資料行印出；前後雙引號用來保留尾端空白，不屬於資料。中文包含雙位元字元與 SO／SI 控制碼，因此解碼後的字數、畫面欄號不等於主機 byte 位置。GENERATE／SYSOUT 另外顯示 CASE、ID 與 EOF-MARKER-AT-014=YES/NO，表示第 14–16 bytes 是否為 EOF；不直接印出可能切到半個中文字的三個 bytes。CASE 0003 為 YES，所以不轉換；CASE 0005 的 EOF 位於第 12–14 bytes，判斷為 NO，仍轉換。公司、姓名、地址及備註均為虛構中文；未知代碼留空，數字欄位保留數字。這是測資輸出，尚未實作需求中的預覽功能。

每筆輸出中的 BEFORE-ID 是這一次執行 CKP02 前的實際識別值，ACTUAL-ID 是執行後的實際值，EXPECT-ID 是預期結果。CHECK2 的 BEFORE-ID 來自第二次執行前的快照，應等於 CHECK1 的 ACTUAL-ID。

BEFORE-ID="0000123456"
ACTUAL-ID="00123456  "
EXPECT-ID="00123456  "

CHECK2 / CASE 0004
BEFORE-ID="00123456  "
ACTUAL-ID="123456    "
EXPECT-ID="123456    "

先從 JESYSMSG 確認 SNAP1、SNAP2 都有執行且 RC 0。這份輸出呈現識別值的前後差異；PASS 仍代表整筆 400 bytes 符合預期，不是只比對顯示的十個字元。

CHECK1、CHECK2 應各有七筆 PASS ALL 400 BYTES，結尾為 CHECKED=0007 ERRORS=0000；RUNONCE、RUNTWICE、RUNEMPTY 均應 RC 0。CCKP 的 RC 4 必須與 README 列出的編譯警告核對，不能只看整體 return code。

CKP02 沒有呼叫 IMS，因此這些紀錄不能用來判斷 IMS 交易是否完成。若缺少某個 step 的紀錄，先從相同 job ID 補下載，再請 Bob 接著確認。

紀錄中出現額外的控制字元？

JES 系統紀錄使用 tcb-jobs（IBM-1047）可避免本次遇到的行尾 NEL。CHECK1、CHECK2 已改用雙引號，使用 tcb-jobs 可正確顯示且沒有行尾 NEL。含中文的編譯清單仍使用 IBM-937，RSE 回應可能在行末保留 NEL，正常換行仍存在。先保留下載原檔；請 Bob 分析時忽略行末的 NEL，不要因此切換成 IBM-1047，以免中文顯示錯誤。若需整理閱讀版，另存副本並保留原始紀錄。

延伸：IMS 交易到底完成了沒有？

看到一行錯誤記錄，往往還不能知道整筆交易的結果。先把前後事件串起來，再決定要往哪裡查。

這份 CSV 是練習用的 IMS 事件摘要，欄位定義在 log-schema.md。它已經整理成可閱讀的事件，和主機原始 binary log 不同。
