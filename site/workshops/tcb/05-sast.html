查詢弱點修補

看懂問題，再動手修正

對照弱點報告與程式，修正查詢並檢查原本的功能。

拿到弱點報告，從哪裡開始？

先把報告和對應程式放在一起，理解問題怎麼發生，再請 Bob 協助修正。這份練習使用 SQLite 查詢程式和一筆 SQL 注入報告。

1. 先看懂問題

Ask 模式

加入檔案：samples/reports/sast.json、samples/python/customer_lookup.py

對照報告與程式
這份弱點報告指出查詢程式可能有 SQL 注入。請幫我對照程式，說明問題出在哪裡、什麼輸入會造成影響，以及可以怎麼修正。
預期回應

從輸入到 SQL 執行的問題位置，以及修正建議。

回覆應帶你從輸入值看到 SQL 執行的位置。看懂原因後，再討論怎麼改，會比直接接受修改更容易掌握結果。

2. 修正並保留正常功能

sast-task.md 列出要保留的介面、測試和報告內容。正常查詢也要測，例如姓名或識別值中本來就有單引號的情況。

Agent 模式

加入檔案：specs/sast-task.md、samples/reports/sast.json、samples/python/customer_lookup.py

完成查詢修正
請依 specs/sast-task.md 修正這個查詢問題，保留函式介面與正常查詢功能，把修正存到 output。

請用測試確認問題輸入與正常資料的處理結果，保留原有測試，再記錄修改理由和實際測試結果。
預期回應

修正後的程式、六個查詢測試結果，以及修補報告。

Agent 模式

加入檔案：specs/sast-task.md

再檢查一次結果
請依 specs/sast-task.md 再檢查一次修正結果，確認正常查詢和異常輸入都有測到，並更新修補報告。
預期回應

查詢測試結果，以及更新後的修補報告。

六個測試通過後，開啟 customer_lookup.py 和 sast-remediation.md 比較修改。若是正式掃描報告，修正後還需要由原掃描工具重新檢查。

修正時可以留意什麼？

查詢值應透過參數傳入。直接刪掉引號，雖然可能擋住某些輸入，也會破壞像 O'NEIL 這樣的合法資料。
