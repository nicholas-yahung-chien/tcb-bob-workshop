程式碼檢查與改善

檢查問題，再驗證修改

使用 ZCodeScan 與 Improve Code，改善 CKP02 錯誤處理並驗證結果。

完整版 · 切換至簡易版

程式跑得動，遇到讀寫失敗時呢？

前面已看過 CKP02 的轉換結果。這一節使用 ZCodeScan 與 Improve Code 檢查程式，再替檔案讀寫補上錯誤處理。

本節在本機修改 COBOL，完成後重新掃描並整理結果。修改範圍見 host-lab/CODE-QUALITY.md。

1. 先準備可修改的副本

Agent 模式

檔案位置（供核對）：host-lab/CODE-QUALITY.md、z-lab/CKP02.cbl

準備這次的練習
我想接著改善 CKP02.cbl 的檔案錯誤處理。請依 CODE-QUALITY.md，先幫我準備 CKP02H 的副本和修改前備份，原版保留。這一步先不要改處理邏輯，讓我可以先做掃描。
預期回應

host-lab/hardening/CKP02H.cbl 與 before.txt；業務邏輯保持原樣。

確認 host-lab/hardening/CKP02H.cbl 已建立，PROGRAM-ID 為 CKP02H，其他業務邏輯與原版相同。這是保留在本機的改善練習程式。before.txt 保存改善前的副本，之後可用 Select for Compare 比較修改。

2. 用 ZCodeScan 看實際檢查結果

  1. 儲存並保持開啟 CKP02H.cbl，等待 COBOL 語言服務完成載入。
  2. 開啟命令選擇區，執行 IBM Z Open Editor: Execute IBM ZCodeScan。
  3. 在 Problems 檢視查看結果，保留規則名稱或代碼、行號與完整訊息。語法診斷、編譯警告與 ZCodeScan 訊息分開記錄。
  4. 切換至 Z Code，加入下方檔案並送出提問，讓 Bob 使用 ZCodeScan 取得結果。這可能重新掃描目前儲存的版本，不是自動讀取先前面板的快照。

先處理語言服務回報的語法錯誤。未設定 ZCodeScan 的 ZAPP profile 時會採用預設規則；若工作區已有自訂規則或 baseline，請記錄設定，避免把被隱藏的診斷當成已修正。

若找不到命令或出現權益／語言服務錯誤，先確認 IBM Z Open Editor 已啟用、Bob 已登入及 PPZ 權益。登入或切換團隊後可執行 Developer: Reload Window，重新檢查權益。仍無法執行時先做來源審閱，將掃描標為「未執行」。沒有診斷也要記下實際狀態；它不代表程式沒有任何風險。

Z Code 模式

檔案位置（供核對）：host-lab/CODE-QUALITY.md、host-lab/hardening/CKP02H.cbl

一起看檢查結果
請用 ZCodeScan 檢查目前這支 CKP02H.cbl，先不要修改程式。請列出你實際取得的訊息和行號，幫我說明哪些值得優先處理，並和「問題」面板中的結果核對。工具找到的問題和你另外提出的建議請分開。如果無法取得掃描結果，請直接告訴我。請一併參考 CODE-QUALITY.md。
預期回應

實際 ZCodeScan 訊息與行號、和問題面板的核對、處理優先順序，以及另外提出的改善建議；程式保持不變。

展開 Bob 的工具執行紀錄，確認有取得 ZCodeScan 診斷，再抽查訊息與行號是否和「問題」面板一致。不要只核對總數；不同版本、規則或篩選條件可能造成差異。命名與寫法建議也不等於安全弱點，不必全部照單修改。若工具無法取得結果，可將面板中的完整訊息複製貼入對話，再請 Bob 分析。

3. 試用 Improve Code，再決定修改範圍

在 CKP02H.cbl 選取包含 OPEN、READ、REWRITE 的處理段落，按右鍵選 IBM Bob → Improve Code。這是 Bob 的程式改善功能，會開啟新的 Agent 任務，可能依權限直接修改副本；它不等同 ZCodeScan，也不保證自動執行掃描。先看任務內容與檔案差異，再接受修改。

新任務若未帶入本節背景，加入 host-lab/CODE-QUALITY.md，說明這次只改善檔案錯誤處理。比較 before.txt 與 CKP02H.cbl，確認轉換條件、欄位位置與重跑結果沒有改掉。接著切到 Plan，討論要採用哪些修改。

Plan 模式

檔案位置（供核對）：host-lab/CODE-QUALITY.md、host-lab/hardening/CKP02H.cbl、host-lab/hardening/before.txt

討論要怎麼改
我想先把 CKP02H.cbl 的檔案讀寫失敗處理補完整，正常轉換和重跑邏輯維持原樣。請看看剛才 Improve Code 的修改或建議，哪些適合留下、還缺什麼。這次只在本機修改並重新做 ZCodeScan，不準備 JCL，也不上傳或執行主機作業。請先說明修改做法和重掃描時要比較的地方，我們確認後再改。請一併參考 CODE-QUALITY.md。
預期回應

本機修改方案與重新掃描的比較重點；尚不修改程式，不安排主機作業。

Bob 建議用 start_subtask 執行，該怎麼繼續？

start_subtask 是 Bob 內建的「建立子任務」工具，由 Bob 呼叫，不需要在終端機輸入或另外安裝 MCP。子任務有自己的對話與進度，你可以查看修改並繼續互動。詳見 IBM 工具說明。

Plan 可能將工作拆成新增欄位、診斷段落、OPEN／READ／REWRITE／CLOSE 處理等項目，再建議切換 Agent 依序執行。項目與數量依實際計畫而定；不需要照抄固定的六項。確認計畫後，切換 Agent，使用下方回覆即可。若 Bob 沒有拆成子任務，也可直接依同一份計畫完成。

每個子任務應閱讀同一份計畫與 CODE-QUALITY.md，完成後更新進度並讓你核對差異，再進行下一項。若另開對話，加入實際計畫檔，避免遺漏先前同意的限制。完成子任務後，回到第 5 步重掃描並比較結果。本節不做執行測試，報告只記錄來源審閱與實際掃描的結論。

4. 完成同意的程式修改

確認計畫符合本次範圍後，切換至 Agent。沿用剛才的計畫；若 Bob 已產生計畫檔，將該檔一併加入對話。若舊計畫仍包含 JCL、上傳或主機測試，請先調整為本機修改與重新掃描。

Agent 模式

檔案位置（供核對）：host-lab/CODE-QUALITY.md、host-lab/hardening/CKP02H.cbl、host-lab/hardening/before.txt

完成同意的修改
同意這份計畫，請依 CODE-QUALITY.md 完成本機的 CKP02H.cbl 修改，保留原版與原本的轉換、重跑邏輯。若分成子任務，請沿用同一份計畫，完成後帶我看差異和修改原因。最後重新做 ZCodeScan，這次先不安排主機執行。
預期回應

本機 CKP02H.cbl 的修改差異與原因；不產生 JCL 或進行主機操作。

成果保存在 host-lab/hardening/：CKP02H.cbl、before.txt 與 review.md。各學員的修改可能不同，請保留自己的差異與理由；本節不產生執行用 JCL，也不將修正版上傳主機。

5. 重新掃描，比較改善前後的結果

儲存並保持開啟 CKP02H.cbl，切換至 Z Code，直接送出下方提問，讓 Bob 使用相同規則重新執行 ZCodeScan 並整理結果。不需要先手動掃描或貼上最新訊息。若另開對話，可加入先前保存的修改前掃描紀錄；找不到時先記錄本次結果與比較限制。

Z Code 模式

檔案位置（供核對）：host-lab/CODE-QUALITY.md、host-lab/hardening/CKP02H.cbl、host-lab/hardening/before.txt

重新掃描並整理結果
程式改好了，請幫我用 ZCodeScan 再掃一次 CKP02H.cbl，看看之前的問題改善了哪些，還有哪些要留意。如果找不到上次的結果，就先說明這次掃到的問題。先不用再改程式，幫我把結果整理到 review.md 就好。請一併參考 CODE-QUALITY.md。
預期回應

這次的掃描結果、和上次相比的變化，以及還要留意的問題，整理在 host-lab/hardening/review.md。

展開工具執行紀錄，確認這次真的執行 ZCodeScan 並取得修正版的訊息；不能只使用編輯過程中的一般 IDE 診斷代替。找不到修改前的紀錄時，先整理這次掃描結果，並註明比較範圍。

逐項比較哪些訊息已消失、哪些仍存在，以及是否新增問題。修改後行號可能改變，請搭配規則與程式位置核對，不只比較總數。各學員不必得到相同數量，也不以「零警告」作為完成條件；保留的項目應說明理由。

完成後，保留程式修改差異、重新掃描的結果與 review.md。本節到此結束；日後要將修正版部署到主機時，還需要編譯及執行測試。

延伸閱讀：CIS14 的 IMS 呼叫與錯誤處理

想將相同方法用在 IMS 程式時，搭配客戶範例 CIS14 與 Copybook 做來源審閱。課程 IMSCKP／IMSEVT 的教學資料庫不是 CIS14 的正式資料庫，不能直接拿來執行 CIS14。

Ask 模式

檔案位置（供核對）：host-lab/CODE-QUALITY.md、z-lab/CIS14/CIS14.cbl、z-lab/CIS14/

看看 IMS 程式可以改善什麼
如果換成 CIS14.cbl 這支 IMS 程式，有哪些地方值得先改善？請幫我看每次呼叫後有沒有檢查正確的狀態，失敗後會怎麼處理，以及紀錄是否足以查問題。請指出程式依據，缺少資料的地方先列出，先不要修改。請一併參考 CODE-QUALITY.md。
預期回應

對照實際程式與工具結果，說明已確認事項和待驗證項目。

先核對呼叫使用哪個 PCB、如何判斷狀態，以及錯誤後會做什麼。缺少的程式、DBD／PSB 與執行設定先列出，再決定可驗證的修改範圍。識別資料能否輸出須依資料性質與客戶規範判斷，不能只憑 DISPLAY 就認定為弱點。

工具說明與適用範圍

IBM ZCodeScan 操作說明、Bob 與進階功能權益。請以自己 IDE 的實際訊息為準；靜態檢查、AI 審閱與主機測試各自提供不同證據。
