16:07–16:12 · 講師短示範

從 finding 走到修補與回歸測試

以合成 SQL 注入題示範可檢查的修補流程。

5分鐘短示範：finding → code → fix → test

前1分鐘核對source/sink，中間2分鐘請Bob修補，最後2分鐘檢查測試與剩餘風險。合成finding為CWE-89 SQL注入，使用本機記憶體SQLite與虛構資料，不對銀行系統執行攻擊。

本題不是Fortify／Checkmarx實際掃描結果。用它練習接收報告後的處理方式：先證實資料流、最小修補、回歸測試、再交給正式工具複掃。

從報告修補

SQL注入修補 · Agent
請讀AGENTS.md、samples/reports/sast.json、samples/python/customer_lookup.py和tests/test_lookup.py。
使用Agent核對finding的source到sink；在output/customer_lookup.py修補SQL注入，介面仍為lookup(connection,customer_id)，以參數綁定處理值，不採字元刪除或手動跳脫。
執行 python scripts/verify.py sast，失敗則修正output/後再測，不改tests/。
建立output/sast-remediation.md：finding ID、原始檔案行號、成因、修改、實際測試結果、剩餘風險、待正式SAST工具複掃。
本題是SQLite合成範例與教學finding，不能宣稱修好了合庫COBOL或已經Fortify/Checkmarx複掃。只寫output/。

驗收

python scripts/verify.py sast

6項測試驗證正常查詢、未知值、合法單引號、注入字串、表仍存在及參數綁定。正確修補應保留O’NEIL這類合法資料語意；把引號刪掉不是修補。

COBOL／HLASM finding必須對照實際報告與資料流。不能把無條件REWRITE直接稱為已證實的資安漏洞，也不能把本SQLite修補宣稱為合庫程式修補。
