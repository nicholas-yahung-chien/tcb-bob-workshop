16:07–16:12 · 實作練習

從 finding 走到修補與回歸測試

以合成 SQL 注入題示範可檢查的修補流程。

任務目標

練習從弱點報告定位source與sink，完成最小修補並檢查回歸測試。先用5分鐘走過finding → code → fix → test，再延伸閱讀修補報告。

本題為CWE-89 SQL注入的合成finding，搭配本機SQLite與虛構資料；Fortify／Checkmarx報告可沿用相同的定位、修補及複掃步驟。

Step 1 · 加入報告與程式

在Bob模式選單選取 Agent，用 @ 加入下方Prompt列出的檔案，再貼上內容送出。

根據finding修補 · Agent
請讀AGENTS.md、samples/reports/sast.json、samples/python/customer_lookup.py和tests/test_lookup.py。
使用Agent核對finding的source到sink；在output/customer_lookup.py修補SQL注入，介面仍為lookup(connection,customer_id)，以參數綁定處理值，不採字元刪除或手動跳脫。
先建立output/sast-remediation.md：finding ID、原始檔案行號、成因、修改、測試結果（尚未執行時標為待驗證）、剩餘風險、待正式SAST工具複掃。
再執行 python scripts/verify.py sast，失敗則修正output/後再測，不改tests/。將實際結果更新到報告，不預先宣稱測試通過。
本題是SQLite合成範例與教學finding，不能宣稱修好了合庫COBOL或已經Fortify/Checkmarx複掃。只寫output/。

Step 2 · 檢查修補與測試

在Bob模式選單選取 Agent，用 @ 加入下方Prompt列出的檔案，再貼上內容送出。

確認參數綁定與回歸結果 · Agent
請在目前教材工作區執行python scripts/verify.py sast。Windows若只有py指令，改用py -3。
展開實際執行結果，回報exit code、通過與失敗項目；不要修改來源或驗收程式。若檢查失敗，先說明原因與最小修正建議，等我確認後再改output。

6個測試包含正常查詢、未知ID、合法單引號、注入字串、資料表保留及參數綁定。開啟修改差異，確認沒有用刪除引號破壞O’NEIL等合法資料。

Step 3 · 閱讀修補報告

核對finding ID、來源行號、修補方式、實際測試與剩餘風險。正式工具複掃是獨立步驟；本機測試通過不能代替正式掃描結果。
