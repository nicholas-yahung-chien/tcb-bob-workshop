程式碼檢查與改善

檢查問題，再驗證修改

使用 ZCodeScan 與 Improve Code，改善 CKP02 錯誤處理並驗證結果。

程式跑得動，遇到讀寫失敗時呢？

前面已確認 CKP02 的轉換結果。這一節接著使用 ZCodeScan 與 Improve Code 檢查程式，再替檔案讀寫補上錯誤處理。本節使用 COBOL 與 JCL，不需要 Python；也不實作需求單中的預覽功能。

有效 PP4Z 權益與本機語言服務正常時，ZCodeScan 可以檢查本機來源；編譯及執行測試仍使用課程主機。修改範圍與測試指引在教材 host-lab/CODE-QUALITY.md。

1. 先準備可修改的副本

Agent 模式

加入檔案：host-lab/CODE-QUALITY.md、z-lab/CKP02.cbl

準備這次的練習
我想接著改善 CKP02 的檔案錯誤處理。請依 CODE-QUALITY.md，先幫我準備 CKP02H 的副本和修改前備份，原版保留。這一步先不要改處理邏輯，讓我可以先做掃描。
預期回應

host-lab/hardening/CKP02H.cbl 與 before.txt；業務邏輯保持原樣。

確認 host-lab/hardening/CKP02H.cbl 已建立，PROGRAM-ID 為 CKP02H，其他業務邏輯與原版相同。這是新的改善練習程式，尚未上傳主機。before.txt 保存改善前的副本，之後可用 Select for Compare 比較修改。

2. 用 ZCodeScan 看實際檢查結果

  1. 開啟 CKP02H.cbl，等待 COBOL 語言服務完成載入。
  2. 開啟命令選擇區，執行 IBM Z Open Editor: Execute IBM ZCodeScan。
  3. 在 Problems 檢視查看結果，保留規則名稱或代碼、行號與完整訊息。語法診斷、編譯警告與 ZCodeScan 訊息分開記錄。
  4. 將實際訊息貼入 Bob，與目前程式一起分析；不要將候選改善項目當成工具已找到的問題。

先處理語言服務回報的語法錯誤。未設定 ZCodeScan 的 ZAPP profile 時會採用預設規則；若工作區已有自訂規則或 baseline，請記錄設定，避免把被隱藏的診斷當成已修正。

若找不到命令或出現權益／語言服務錯誤，先確認 IBM Z Open Editor 已啟用、Bob 已登入及 PP4Z 權益。登入或切換團隊後可執行 Developer: Reload Window，重新檢查權益。仍無法執行時先做來源審閱，將掃描標為「未執行」。沒有診斷也要記下實際狀態；它不代表程式沒有任何風險。

Ask 模式

加入檔案：host-lab/CODE-QUALITY.md、host-lab/hardening/CKP02H.cbl

一起看檢查結果
請幫我看剛才的檢查結果，對照程式說明問題在哪裡、會有什麼影響。如果讀檔或回寫失敗，現在會怎麼處理？請把工具實際找到的問題和你另外建議改善的地方分開，先不要修改。
預期回應

對照實際程式與工具結果，說明已確認事項和待驗證項目。

3. 試用 Improve Code，再決定修改範圍

在 CKP02H.cbl 選取包含 OPEN、READ、REWRITE 的處理段落，按右鍵選 IBM Bob → Improve Code。這是 Bob 的程式改善功能，會開啟新的 Agent 任務，可能依權限直接修改副本；它不等同 ZCodeScan，也不保證自動執行掃描。先看任務內容與檔案差異，再接受修改。

新任務若未帶入本節背景，加入 host-lab/CODE-QUALITY.md，說明這次只改善檔案錯誤處理。比較 before.txt 與 CKP02H.cbl，確認轉換條件、欄位位置與重跑結果沒有改掉。接著切到 Plan，討論要採用哪些修改。

Plan 模式

加入檔案：host-lab/CODE-QUALITY.md、host-lab/hardening/CKP02H.cbl、host-lab/hardening/before.txt

討論要怎麼改
我想先把檔案讀寫失敗時的處理補完整，正常轉換和重跑結果維持原樣。請看看剛才 Improve Code 的修改或建議，哪些適合留下、還缺什麼，以及要怎麼測。先說明做法，我們確認後再改。
預期回應

對照實際程式與工具結果，說明已確認事項和待驗證項目。

4. 完成修改，準備主機測試

Agent 模式

加入檔案：host-lab/CODE-QUALITY.md、host-lab/hardening/CKP02H.cbl、host-lab/run.jcl、host-lab/environment.md

完成同意的修改
請照剛才同意的做法完成 CKP02H，並依 CODE-QUALITY.md 準備這次的 JCL。原版程式和測試預期值保留。也請簡單記下改了哪些地方，以及哪些情況還需要上主機測試，讓我檢查後再提交。
預期回應

CKP02H.cbl、run-quality.jcl 與 review.md；主機測試待執行。

成果放在 host-lab/hardening/：CKP02H.cbl、run-quality.jcl 與 review.md。依 CODE-QUALITY.md 核對 JCL，再透過 tcb-rse 將程式上傳到自己 TCBLAB.COBOL 的新成員 CKP02H。重新開啟確認中文、換行與 PROGRAM-ID，從本機 run-quality.jcl 提交，記下新 job ID。原版 CKP02 與 RUN 保留。

5. 重掃描，再看主機實際結果

對修正版再執行同一個 ZCodeScan 命令，使用相同規則設定，保存新訊息。將這次實際提交的 JCL、掃描結果與完整作業紀錄加入 Bob；請指定實際下載的資料夾。中文 PRINTDD 依第 03 單元的方式開啟並另存 UTF-8。

Agent 模式

加入檔案：host-lab/CODE-QUALITY.md、host-lab/hardening/CKP02H.cbl、host-lab/hardening/run-quality.jcl

確認改善是否有效
這是修正版的掃描結果和主機紀錄，請幫我確認修改是否有效，正常轉換有沒有受到影響。請指出實際 job、步驟和訊息，也看看新增的錯誤處理有哪些真的測到、哪些還沒測。依 CODE-QUALITY.md 把結果記在這次的測試報告裡。
預期回應

host-lab/hardening/test-report.md；另外加入本次掃描訊息及實際作業資料夾。

CHECK1、CHECK2 各七筆 PASS、CHECKED=0007 ERRORS=0000，以及 RUNEMPTY RC 0，是正常流程的回歸證據。它們不會自動證明新增的錯誤分支正確；依 CODE-QUALITY.md 另外準備隔離的失敗案例。未執行的案例仍列為待驗證。若出現 RC 4，依第 04 單元的方法追到實際診斷，不直接歸因於此次修改。

延伸閱讀：CIS14 的 IMS 呼叫與錯誤處理

想將相同方法用在 IMS 程式時，搭配客戶範例 CIS14 與 Copybook 做來源審閱。課程 IMSCKP／IMSEVT 的教學資料庫不是 CIS14 的正式資料庫，不能直接拿來執行 CIS14。

Ask 模式

加入檔案：host-lab/CODE-QUALITY.md、z-lab/CIS14/CIS14.cbl、z-lab/CIS14/

看看 IMS 程式可以改善什麼
如果換成 CIS14 這支 IMS 程式，有哪些地方值得先改善？請幫我看每次呼叫後有沒有檢查正確的狀態，失敗後會怎麼處理，以及紀錄是否足以查問題。請指出程式依據，缺少資料的地方先列出，先不要修改。
預期回應

對照實際程式與工具結果，說明已確認事項和待驗證項目。

先核對呼叫使用哪個 PCB、如何判斷狀態，以及錯誤後會做什麼。缺少的程式、DBD／PSB 與執行設定先列出，再決定可驗證的修改範圍。識別資料能否輸出須依資料性質與客戶規範判斷，不能只憑 DISPLAY 就認定為弱點。
