COBOL 文件化

把程式讀懂，也讓下一個人看得懂

用 PPZ 解讀程式，再整理成方便查閱的文件。

下次接手的人，會想問哪些問題？

知道程式「大概在做什麼」之後，還需要留下欄位、流程和注意事項。這個練習會用 PPZ 解讀 CKP02，再把說明整理成方便查閱的文件。

沿用第 01 單元產生的 output/CKP02-data-dictionary.md，接著閱讀解說與產生文件。尚未完成時，請先回到建立 DD.json 與可閱讀的資料字典。

1. 用 Explain code 閱讀程式

  1. 開啟 z-lab/CKP02.cbl，選擇 Z Code。
  2. 點 Start Workflow，在工作區選單選擇本機教材資料夾的 Run Workflow in〈你開啟的教材資料夾名稱〉，並核對下方顯示的本機路徑。
  3. 在 Bob workflows 找到 Explain code，點右側的 Start。
  4. 依流程選取這個檔案及 Developer 視角，閱讀程式說明。

閱讀解說時，對照第 01 單元建立的可閱讀資料字典，看看欄位用途是否一致。有疑問時，把 output/CKP02-data-dictionary.md、DD.json 和解說文件一起加入對話，請 Bob 對照 CKP02 找出差異。

Explain code 使用教材中的 cobol-explain-zh-tw skill。完成後從結果連結開啟文件，閱讀中文說明；程式名稱與識別字會保留原文。文件仍是英文時，請參考中文文件的排解步驟。

回覆談到轉換條件後，可以追問實際執行時會遇到的情況，例如同一份資料再跑一次。

Z Code 模式

加入檔案：z-lab/CKP02.cbl、requests/change-application.docx

追問執行時的行為
如果資料符合或不符合轉換條件，接下來分別會執行哪些動作？何時會讀下一筆，何時結束？請沿著程式段落說明。

再用識別欄位 0000123456 的重跑案例（第 14–16 位不是 EOF），追蹤同一資料集中的同一筆記錄。這裡是兩次獨立的 CKP02 程式執行：第一次寫回的結果，作為第二次的輸入；不是一次處理迴圈讀取兩筆不同資料。請逐步列出每次輸入、是否符合轉換條件及寫回結果，保留尾端空白。

若要說明 JCL 或排程是否會防止重複處理，請先讀取並引用實際 JCL 或設定。只有 COBOL 來源時，將這些外部控制保留待確認，不自行假設有防重機制。
預期回應

不符合條件和重跑時的處理過程，附上對應程式位置。

延伸閱讀：用 IDSHIFT 認識 Copybook 與 JCL（選做）

IDSHIFT 是獨立的教學範例，用來練習辨識 Copybook、子程式呼叫與 JCL 的關係。它處理記憶體中的單筆資料，並非 CKP02 的新版，也未實作需求單中的試跑與統計功能。你可以略過這段，直接進行下一步 CKP02 文件化。

想比較兩種寫法時，再把下列檔案一起交給 Bob：IDSHIFT 使用 IDREC.cpy 定義資料，由 TESTSHIFT 呼叫；範例 JCL 執行 TESTSHIFT。請從檔案找出這些關係的依據。

2. 整理成接手文件

保持 Z Code，點 Start Workflow，先選擇本機教材工作區，再於 Bob workflows 找到 Generate program documentation，點右側的 Start。依流程選取 CKP02.cbl，完成後從結果連結開啟產生的文件。

直接開啟工作流程產生的文件，先目視確認段落與圖表沒有截斷、標題或章節沒有重複合併，再核對表格與關鍵數值。工作流程顯示完成，仍須進行內容驗收。原稿保留在 docs/；把這份文件加入 Bob 對話，切換到 Plan，列出需要補齊或更正的內容，後續對照原始碼將修正整理到 output/ 的接手文件。

這裡也加入需求申請單與前面釐清的內容：程式說明回答「現在怎麼運作」，影響分析則回答「為了新需求，接下來要改什麼」。兩份資料一起看，才能區分既有功能與新增工作。

對照文件時，可以先看哪些地方？
  • 資料內的 EOF 會略過這一筆的轉換，接著仍會讀下一筆；READ 的 AT END 才會設定迴圈使用的 EOF 旗標。
  • 記錄第 14–16 位，對應 R-NAME 的第 3–5 位。閱讀欄位位置時，先看看是從哪裡起算。
  • 程式宣告 VALUE SPACE；實際空白編碼與資料集屬性，需要搭配主機環境確認。
  • 課程的 z-tests/run.jcl 編譯並執行 CKP02 與測試輔助程式；生產環境 JCL 尚未提供。只有選做 IDSHIFT 時，才另核對 samples/jcl/IDSHIFT.jcl 執行 TESTSHIFT。

請 Bob 依 DOC-SPEC.md 核對格式與數值，再由你對照原始碼確認，不需要執行驗收腳本。

重跑的例子，應該怎麼看？

使用教學重跑案例 0000123456，並讓第 14–16 位不是 EOF。第一次轉換得到 00123456 加兩個空白，第二次得到 123456 加四個空白。第一次後仍以 00 開頭，所以不能只用一個例子就認定重跑結果都相同。

output 裡會有 program.md、impact-analysis.md 和 facts.json。前兩份方便閱讀，facts.json 則用來檢查欄位及例子是否一致。
