# COBOL 程式碼檢查與改善

第 05 單元改善 CKP02 的檔案錯誤處理，修改後僅重新執行 ZCodeScan。各學員可以採用不同的實作方式，完成後比較修改差異與掃描結果。本節以本機練習為範圍，提問可從課程網頁複製。

簡易版先挑一個檔案錯誤處理問題，確認方案後修改，再重新掃描。下方列出完整改善範圍，未納入這次方案的項目可留到課後，不必一次完成所有修改。

## 成果與保留範圍

只在 host-lab/hardening 保存 CKP02H.cbl、before.txt、review.md 及必要的本機計畫檔。before.txt 保存改為 PROGRAM-ID CKP02H 後、尚未改善的來源。既有成果先比較，不覆寫不同版本。保留 z-lab、z-tests、原版 JCL 及前面課程的報告。目錄名稱 host-lab 不表示本節需要主機執行。

請先和 Bob 確認本次計畫以本機修改、重掃描為範圍。若拆成子任務，各項都沿用同一份計畫與本指引。

Improve Code 會建立 Agent 任務，可能修改選取程式。新任務不保證帶入前一段對話，須先讀本指引與工作區規則。逐項審閱差異，不任意重構或改變業務條件。

## 改善範圍

檢查 SELECT 的 FILE STATUS 與 OPEN、READ、REWRITE、CLOSE 的處理。新增狀態欄位，區分成功、正常檔尾及其他 I/O 失敗。開檔失敗不能繼續讀寫，讀取失敗不能回寫未確認的記錄。錯誤退出時關閉已開啟的檔案，後續 CLOSE 不可掩蓋原始錯誤。

本練習的設計目標為 I/O 失敗回傳 12、正常及空檔回傳 0；這些是預期行為，本節不安排執行測試。診斷印出程式名、操作及 FILE STATUS，不印整筆客戶資料。原地更新沒有自動回復能力，中途失敗時之前成功回寫的資料可能已改變。

保留 400-byte 記錄布局、中文資料、轉換條件與讀寫範圍。IN-REF-REC(14:3) 的 EOF 標記與實體檔尾不同。第 0004 筆第二次仍會轉換是原版行為，本節不改成冪等。不修改 fixtures.json 或 CHKCKP 預期值。固定格式 COBOL 保留有效欄位及第 7 欄。來源審閱不能證明修正版的執行結果已與原版一致。

## 掃描與紀錄

儲存並開啟 CKP02H.cbl，在 Z Code 模式明確請 Bob 使用 ZCodeScan。核對工具執行紀錄與實際診斷，抽查「問題」面板中的訊息和行號。無法取得結果時記下原因，也可貼入面板的完整訊息請 Bob 協助。

修改前後使用相同規則設定，保留來源版本及兩次掃描訊息。逐項比較已消失、仍存在與新增的問題；行號改變時依規則及程式位置對照。命名或寫法規範不等於安全弱點，不要求全部消除或所有學員得到相同數量。

review.md 記錄掃描版本／規則設定、來源位置、實際訊息、Bob 額外建議、採用修改及原因，以及保留項目的理由。完成標準是來源差異與實際重掃描結果有據可查。若無法重新掃描，記下原因，請講師協助。

主機編譯、轉換結果、空檔及 I/O 錯誤分支的執行驗證統一註明「本節未執行」，不要求學員接續準備主機測試。掃描無診斷不能寫成執行測試通過，也不能以原版 CKP02 的作業紀錄證明 CKP02H 正確。

## CIS14 延伸範圍

以 z-lab/CIS14 與 Copybook 審閱 GU、GNP、更新及同步呼叫。先確認使用的 PCB，再追查相對應狀態欄位。DISPLAY 的 JOBABEND 文字與實際 ABEND 不同。閱讀時一併列出還需要的 XIDCHK、BRHIDCNV、DBD／PSB 及執行配置。IMSCKP 與 IMSEVT 是不同的教學程式。
