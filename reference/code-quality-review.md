## 本次範圍

以本機 CKP02H 改善 FILE STATUS 與 OPEN／READ／REWRITE／CLOSE 錯誤處理，保留 before.txt、原版及轉換／重跑邏輯。依 CODE-QUALITY.md 僅重新掃描，不準備 JCL、不上傳、不編譯或執行主機作業。

## 修改說明的寫法

例如，若實際新增了 FILE STATUS，可寫「新增狀態欄位，OPEN 失敗時改走錯誤退出，避免接著讀寫；修改位置見本次 diff」。這是示範描述，不代表你的程式已做同樣修改。回傳 12 與正常 0 是本練習的設計約定，未經執行驗證。CLOSE 是否保留原始錯誤與 STOP RUN 是否影響 PERFORM，仍需審閱控制流程。

例如掃描若提示 REDEFINES 的使用，需討論是否值得改寫、改寫會影響哪些欄位關係；不能把訊息直接當作資料損壞或安全漏洞。沒有實際出現此訊息就不列為本次發現。

有修改前紀錄時逐項比較，不只比較總數。缺少時先整理目前結果並說明無法完整比較，不補造原來的警告。工具無法執行則記錄未完成及原因。仍有合理保留項目不等於練習失敗，也不為清空警告而改變業務邏輯。

## 結論

依實際填寫「已取得本次掃描，……項已改善／保留理由為……」或「目前無法取得掃描，未完成重掃描」。主機編譯、轉換正確性、空檔及錯誤分支的執行驗證均為「本節未執行」，不列為學員下一個必做步驟。原版 job 成功不能當作 CKP02H 已驗證。
