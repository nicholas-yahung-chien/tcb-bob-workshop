Bob 好像沒看到我說的檔案

先確認 VSCode 開啟的是練習資料夾。輸入 @ 後，必須從彈出的清單找到並點選檔案；單純在路徑前加 @ 不代表已加入。若清單還開著，先完成檔案選取，再送出問題。若只加入一小段程式，可以再附上整份檔案。

找不到 Z Code 或文件化功能

確認已登入 Bob，且帳號已啟用 Premium Package for Z。重新開啟面板，再看模式選單和上方的 Start Workflow。點選後若先出現工作區選單，選擇顯示本機教材路徑的項目，再到 Bob workflows 找 Explain code 或 Generate program documentation。部分版本將 Z Architecture 顯示為 Z Architect。

Z Understand 是跨應用程式分析使用的額外連線。只有本機程式時，可以先閱讀本機檔案，將其他系統的關係留待確認。

工作流程產生的文件仍是英文

先在 Bob Settings → Skills 確認教材的 cobol-explain-zh-tw 與 program-docs-zh-tw 已啟用，來源為目前的 Workspace。若找不到，確認開啟的是包含 .bob/skills/ 的教材根目錄，執行 Developer: Reload Window 後再查看。

Explain code：執行時應看到「已使用技能 cobol-explain-zh-tw」。若仍產生英文，不必反覆重跑；保留輸出文件，依整理成接手文件的操作，在一般對話中加入該文件並呼叫 /program-docs-zh-tw，產生繁體中文副本。

Generate program documentation：與 Explain code 的語言處理方式不同，不需要等待同樣的技能使用訊息。完成後依課程呼叫 /program-docs-zh-tw，統一台灣繁體中文用語。若 / 清單沒有此項目，先確認技能已啟用；也可以直接加入 .bob/skills/program-docs-zh-tw/SKILL.md 與要整理的文件，請 Agent 依技能內容執行。

主要說明應使用繁體中文；程式名稱、指令及程式碼保留原文。翻譯完成後仍需對照原始碼，確認條件、數值、單位與推論是否正確。

已經有計畫，卻沒有產生檔案

Plan 主要用來討論計畫。確認後，在同一個對話切換 Agent，再請 Bob 依計畫執行。如果換了新對話，把需求、規格和已有計畫一起加入，就能接著做。

出現 Permissions 提示

這是在讓你確認 Bob 接下來的操作。看看檔案範圍和命令，符合這次練習就核准。自己的修改應放在 output；如果操作會改到原始資料或測試，可以先取消，再請 Bob 調整。

Python 指令找不到，或測試失敗

主流程不需要 Python，請依 host-lab/BOB-GUIDE.md 準備與測試。只有選做 Python 範例時，才需確認本機有 Python 3.10 以上版本。Windows 若使用 py，可以請 Bob 改用 py -3 執行。測試失敗時保留完整訊息，讓 Bob 對照需求找原因。

回覆中斷了，怎麼繼續？

先看看 output 已經完成哪些檔案，再請 Bob 從未完成的部分繼續。也可以把問題縮小到一個檔案或一個失敗案例。需要比對時，reference 裡有參考解答。

主機連線或提交逾時

讀取資料或 log 逾時時，先確認個人 profile 與網路，再重新整理。提交逾時則先搜尋自己的 jobs，確認是否已有新的 job ID；不要直接重送。請保留錯誤與發生時間。

CKP02 不需要 IMS region 操作權限。看到其他帳號的資料或操作被拒絕時，不要改用共用管理帳號繼續。

Python 測試通過，代表 COBOL 也通過了嗎？

Python 測試確認的是本機範例。COBOL 還需要在對應的編譯與執行環境測試，IMS 和 JCL 也有各自的設定。把這些結果分開記錄，之後就知道還有哪些要補做。
